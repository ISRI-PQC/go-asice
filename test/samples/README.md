# test/samples — hermetic fixture provenance

Every fixture in this directory is **generated by this repo itself** —
from this repo's own hermetic test PKI (`github.com/isri-pqc/asice/testutil`)
and the `asic` create/verify packages — by the committed generator
`gen/`:

```sh
# from the repo root
go run ./test/samples/gen
```

**Nothing here is copied from any external project.** These files are
SELF-CONSISTENCY PINS: the tests that read them compare values computed
from the same generated artifacts (digests, canonical bytes, shapes),
not external ground truth. The external interop proof against the
Estonian e-voting collector's own fixtures lives in the companion
acceptance harness maintained outside this repo (see README.md).

## Files

### ASiC-E containers (`.bdoc`)

| File | Profile | Contents |
|---|---|---|
| `testEIDBES.bdoc` | BES | 1 data file (`test.txt`), 1 signature (S0) by the primary signer leaf |
| `testMultipleFiles.bdoc` | BES | 2 data files (`test.txt`, `notes.txt`), 1 signature (S0) |
| `testMultipleSigners.bdoc` | BES | 1 data file, 2 signatures (S0 by the primary signer, S1 by the second signer leaf) |
| `testEIDTS.bdoc` | TS | 1 data file, 1 signature (S0) with embedded TST + OCSP in `xades:UnsignedProperties` |

All containers are built by `asic.SignBES` / `asic.SignTS` +
`asic.WriteContainer` over the `testutil` PKI, and the generator
self-verifies each with `asic.Verify` before exiting.

### Extracted golden artifacts

| File | Contents |
|---|---|
| `signatures0EID.xml` | the `META-INF/signatures0.xml` signature document extracted from `testEIDBES.bdoc` |
| `canonicalSignedInfoEID` | the C14N 1.1 canonicalization of that document's `ds:SignedInfo` (what the tests canonicalize and pin) |

The `testutil` PKI shape mirrors the SK test PKI (root → issuer →
signer/OCSP-responder leaves; TSA leaf issued by the root), so
containers generated here exercise the same certificate structure the
external interop harness verifies.

## Determinism

The generator uses a fixed reference time (`2026-08-27T10:00:00Z` —
`testutil` rejects the wall clock) and a fresh PKI per run: the
fixtures are **time-deterministic, not byte-deterministic** (the keys
are random). Re-running the generator refreshes every file; the tests
pass against any single consistent generation because they pin
self-consistency, not absolute bytes.
